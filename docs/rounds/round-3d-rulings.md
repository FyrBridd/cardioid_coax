# Round 3d: decisions made while building the passive crossover

Every ruling the controller made while running plan docs/superpowers/plans/2026-10-30-passive-crossover.md, in order, from the run's ledger. Each says what was decided, why, and what it costs if wrong. Rulings marked "Final:" came from the whole-branch review. Deferred minor findings are listed at the end.

- Ruling P1: SAMPLE and the omni test-Ways helper (`omni_ways(f, level_db=0.0) -> Ways`) live in tests/fakes.py (the existing shared helper module, imported as `from fakes import ...`), not in tests/test_passive.py — several test files need them and test modules importing each other is fragile — cost if wrong: one move.
- Ruling P2: tests shrink grids by monkeypatching the names in the module that uses them (`speaker.passive.BASS_COAX_GRID`, `speaker.passive.LF_HF_GRID`, likewise in semi_active and for fit_active `speaker.xo_fit.*`) — patching only speaker.xo_fit would not reach from-imported names — cost if wrong: slow tests.
- Task 2: Ruling: node layout fixed by controller (brief left order open) — bass L_b1,C_b1,L_b2,Zobel; coax HP C_h1 series + L_h1 shunt to cx; LF L_l1,C_l1,L_l2,notch(series parallel LCR),R_ls,R_lp(at driver); HF C_t1,L_t1,C_t2,R_ts,R_tp,RLC shunt(at driver) — standard ladder order with pads next to the drivers — cost if wrong: Task 3 fits a slightly different circuit, rework is a rebuild of build().
- Task 2: Ruling: BOUNDS keyed by full value name — simplest lookup — cost if wrong: trivial.
- Task 3: Ruling: keep CROSS_WEIGHT (dB gap between the two ways at fb and fh in the objective) — spec §5.3 says the target carries the grid's crossover points; a flatness-only objective let them drift to ~1 kHz, making the grid search meaningless — cost if wrong: the fit trades a little flatness to stay at the grid point; set CROSS_WEIGHT=0 to remove.
- Task 3: Ruling: snapping takes floor-shortfall-reducing moves first when the snapped values break the floor — keeps the hard 3.5 Ω floor (spec anti-goal) ahead of flatness — cost if wrong: slightly worse flatness at snapped values.
- Task 3: Ruling: start_values gains keyword pad_db (level difference) — its signature had no way to get levels — cost if wrong: none (keyword).
- Task 3: Ruling: least_squares ftol=xtol=1e-4 — default hit the eval limit (10 s/fit), snapping dominates the final cost — cost if wrong: slightly less optimal continuous values.
- Task 4: Ruling: fallback test uses a 1.0 Ω bass load, not the brief's 2.0 Ω — at 2.0 Ω the fit clears 3.5 Ω with a 20 mH inductor's DCR, so it doesn't test the fallback — cost if wrong: none.
- Task 4: Ruling: option refits keep the grid stage's polarity — re-searching 4 polarities per option quadruples option cost; polarity mostly set by the crossover points — cost if wrong: a 3rd-order option may be rejected unfairly (deferred, noted for final review).
- Task 4: Ruling: an option is dropped if it breaks a floor the current network meets — spec anti-goal (unsafe load) outranks scores — cost if wrong: none.
- Task 4: Ruling (sent back before review): floor raising (a) runs only while the nominal fit meets its current floor; (b) if a raised-floor refit misses its floor, keep the last fit that met its floor and say in notes the tolerance check still fails; (c) the series fallback triggers only when the final parallel network's z_min < 3.5 Ω (the spec floor), never because of a raised floor — spec §5.3 raises the floor to buy tolerance margin, §7 falls back only when 3.5 Ω can't be met — cost if wrong: a borderline network could be kept with a failing tolerance check (reported to the owner).
- Task 4: Ruling (Important 1, partly plan-mandated "lowest cost"): polarity choice ranks by (floor shortfall, cost) like fit_passive_at's own rank; the grid pick runs xo_fit.pick on the z_ok candidates when any exist, else on all; the fallback note says "No parallel-woofer network in the search clears 3.5 Ω" only when no grid candidate was z_ok — spec anti-goal (unsafe load) and §7 ("no network keeps … 3.5 Ω") outrank the plan's "lowest cost" — cost if wrong: a z_ok network with worse scores is preferred over a better one under the floor (intended).
- Task 4: Ruling (Minor 2 promoted): an option that turns a not-z_ok fit into a z_ok fit is kept regardless of flat23 — mirror of the drop rule; floor outranks scores — cost if wrong: an option kept that costs a little flatness.
- Task 4: Ruling: fallback test with OPTIONS=() accepted — it tests the 2nd-order case where 3.5 Ω is out of reach — cost if wrong: none.
- Task 4: Ruling: floor bought with flatness is acceptable (floor outranks scores) but Task 7's report must show flat23 beside z_min and say when the bass inductors sit at their bounds — carried into Task 7's dispatch — cost if wrong: owner misreads a lossy bass network.
- Task 5: Ruling: delays follow xo_fit's convention (relative, smallest 0), so the coax channel may carry the delay — overrides the brief's "coax: delay 0" — a DSP can delay either channel and xo_fit already does this — cost if wrong: none.
- Task 5: Ruling: semi-active scoring uses the ORIGINAL ways' coax_section and meta — cardioid scores must match the other modes — cost if wrong: none.

- Task 6: Ruling (both Importants): the link scheme isolates sub-networks at their boundaries instead of linking out parts one by one. Five removable links: K1 between IN and C_h1; K2 in series with L_h1; K3 between the bass network output (Zobel on the network side) and the woofers; K4 between the coax LF network output (after R_lp) and the LF driver; K5 between the coax HF network output (after R_tp and the RLC shunt) and the HF driver. Passive: all closed, IN terminal. Semi-active: K1, K2, K3 open; COAX terminal to node cx; BASS terminal straight to the woofers. Fully active: K3, K4, K5 open; HF, LF, BASS terminals straight to their drivers. Shown in the links SVG as a table with K1–K5 open/closed per mode and terminal → node — spec §7.2 says links bypass unused parts; per-part linking leaves LF and HF networks joined at cx in fully active (both drivers driven through each other's networks) and leaves C_h1→IN→L_b1→C_b1 loading cx in semi-active — cost if wrong: the cabinet work may choose different link hardware; the schematic is the one place this is fixed.
- Task 7: Ruling: accept evaluate.responses(ways=...) optional arg and Tolerance per-draw arrays (compare=False) — additive, avoids recomputing ways, feeds tolerance.png — cost if wrong: none.
- Task 7: Ruling: semi-active always uses the parallel network's coax boards, even with a series fallback — the coax boards are identical in both; bass wiring only affects the bass channel — cost if wrong: none.
- Task 7: Ruling: semi-active resistor ratings at the same 25 V rms, stated in network.txt — amp unknown — cost if wrong: ratings re-done when the amp is chosen.
- Task 7: Ruling (plan defect found on real data, fixed in Task 7's fix round, touches Task 3's fit): the passive fit's level is anchored, not free: add a level term to fit_passive_at — LEVEL_WEIGHT × max(0, target − level) where level is the fit's weighted mean 23° dB over [FIT_LO, tl] and target is the bass way's own (× bass_scale) unfiltered smoothed 23° mean over MATCH_BANDS["bass"] minus LEVEL_SLACK_DB = 1.0; the report states system sensitivity (dB at 2 m for 2.83 V at 23°, 300–1000 Hz) and how far it sits below the woofers' own level, for each network incl. series — spec §4 (coax LF needs ~5.5 dB padding, i.e. play at the bass's level) and the anti-goal "hiding the cost"; the plan's "level is free" let the fit buy flatness and the floor with ~7 dB of loss — cost if wrong: the fit trades some flatness or picks the series fallback; the owner then sees the real trade.
- Task 7: Ruling: Minors 1 (semi-active netlist labels the coax input `in`, should be `cx (COAX)`), 2 (false "within 0.25 dB on every trusted score"), 3 (mixed-sign difference column) promoted to the fix round — owner/builder-facing text that misleads — cost if wrong: none.

Add one-sided stopband terms to fit_passive_at: each way's smoothed 23° dB may exceed its acoustic LR4 target (anchored level + LR4 magnitude at the grid point) by at most LEAK_TOL_DB = 3 dB, penalised LEAK_WEIGHT per dB beyond, over the way's stopband ≥ 1 octave from its point (bass f ≥ 2 fb; coax LF f ≤ fb/2 and f ≥ 2 fh; coax HF f ≤ fh/2), within [FIT_LO? no: ways.f range up to tl and FIT_TOP]. Report the semi-active result as found — spec §1 cardioid behaviour of the coax section 150–600 Hz and §5.4 (one set of coax boards for both modes) — cost if wrong: passive flatness gets worse (that is the honest cost).
- Task 7: Ruling: the two re-review leftovers of finding 1 (series parts table in report.html still rated with semi-active; network.txt header says ratings are "the larger of passive and semi-active" for the series network too) go into fix round 2 — they contradict the same ruling in owner-facing output — cost if wrong: none.
- Task 7: Ruling (replaces the LR4 stopband ruling, which was wrong: a 2nd-order section can't follow an acoustic LR4 slope): (1) bass-under-coax term instead — at 23°, smoothed, over [2·fb, 600 Hz] the bass way must sit at least BASS_UNDER_DB = 10 dB under the coax LF way; excess penalised LEAK_WEIGHT per dB per point (point weights as the residual); skip exactly-zero points.
